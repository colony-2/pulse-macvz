# macOS cell provider

Implement `github.com/colony-2/pulse-provider-api.Provider` as an importable Go library with Orchard, direct Tart, and native VZ backends. Also provide a Cobra `pulse-tart server` CLI using the published provider plugin SDK: outbound by default, with inbound support subject to the SDK platform limits. The CLI owns transport and reconciliation, uses flags with double-dash long names and single-character short aliases, and configures macOS, Linux/Docker, and macOS Docker capacity. Share a versioned JSON flags file across `server`, `setup`, and `upgrade`, with explicit CLI flags taking precedence. Setup prepares missing capacity; upgrade drains accepted work before rebuilding owned sources. Neither command installs a background service or replaces the host executable. Do not introduce a private protocol or YAML configuration file. Support macOS ARM64 slots and Ubuntu ARM64 Docker workers; macOS Docker jobs use private Linux companions. Shared volumes are deferred.

**Configuration and ownership.** Both constructors take the same typed `Config`. Require owner; Orchard also requires a private durable state directory; default bases and groups when omitted. `VMCounts` has optional macOS, Linux and total job counts: defaults are 2, 4 and their sum. Explicit zero disables an OS or drains all job capacity; macOS counts above two are invalid. All VMs use 4 vCPU / 8192 MiB; arbitrary envelopes are unsupported. Explicit groups select other bases and share the same count limits. Orchard adds connectivity and worker placement; Tart adds executable/home and SSH/command timeouts. Copy mutable inputs. One runtime locks each Tart home/owner scope (or Orchard state directory) and one host owns each backend/owner scope. Constructors create no VMs; the host explicitly drives reconciliation. `ResolveConfig` exposes the effective configuration without side effects.

**Count limits.** Count primary job VMs, including unused warm workers and existing partial allocations; Orchard also retains ambiguous dispatch reservations. Exclude Docker companions and image builders from job counts. Separately enforce at most two physical macOS instances on the worker, including builders and foreign running/pending VMs; stopped/suspended sources do not count. Reserve counts before dispatch and preserve reservations through recovery and cleanup. Lower limits drain unused capacity without cancelling active jobs. A shared total can be smaller than the sum of OS limits: reclaim idle warm workers to prepare another requested pool, returning `no_capacity` until ready without retaining the rejected lease. Do not automatically resize counts to host resources.

**Bases.** Catalog entries declare a concrete name, digest-pinned OCI image, actual OS version, SSH access, and capabilities. `DefaultBases()` supplies digest-pinned `macos-26-arm64` (Tahoe 26.6.2), then `macos-15-arm64` (Sequoia 15.7.7), with independent mutable values. Omitted configuration selects both macOS versions and `DefaultLinuxBase()` (Ubuntu 24.04 ARM64). Conventional groups cover every configured base, with separate templates sharing the same OS and total job limits; either macOS version may use both macOS positions. Linux bases accept `Arch: "arm64"` (the default) or `Arch: "amd64"`; macOS bases require ARM64. Direct Tart requires a matching native host architecture. Intel binary translation inside ARM guests is unsupported. Ubuntu 26.04 ARM64 and AMD64 VM sources are built separately; default image digests change only after publication and qualification. Linux includes Docker; macOS Docker remains opt-in. Verify the exact configured OS version regardless of the major-version base label. Selectors match concrete names case-sensitively; each `*` anywhere matches zero or more characters, including `/`, with all other characters literal. Labels are valid UTF-8, 1–4096 bytes, without NUL, spaces, tabs, CR or LF; concrete names cannot contain `*`. There are no aliases. `GetCapabilities` returns the complete configured catalog and capability sets in `Config.Bases` preference order, independent of slot occupancy/readiness/count. Return copied data without secrets or backend calls; honor cancellation and closed runtimes. Admission prefers the first fitting available base in that order. Capabilities use exact all-of set semantics. Verify OS version and configured built-in tool capabilities inside each template before readiness.

**Prepared images.** Reconciliation adopts named local sources or prepares missing ones. Install Nix/c2j/tools once into a shared stopped base, then independently clone, configure and boot a template per slot. Install Docker engine packages with apt during base preparation, never during allocation. macOS companions clone a reusable Linux source keyed by registry image and engine version; Linux worker bases include the selected engine version. Allocate private writable Docker disks and fresh identities per job generation. Resolve `Config.C2JVersion` (`latest` by default, or a tag/commit) only for missing base installation. No c2j version is compiled into the library; existing images survive library/version-selector changes. The setup archive is internal, with no public bundle configuration. No release manifest or installed-version sidecar; inspect `c2j version`.

**Independent updates.** A standalone local Tart script uses the same guest preparation scripts to build a base and every requested suspended template before publication. Stable names identify owner/base/group/size/slot, not c2j version. Give cold macOS builders fresh MACs and Mac machine identifiers (`--random-serial`) before boot; preserve those identifiers in publication and suspended job clones. Publish canonical names and matching Orchard worker-local aliases using `tart clone --overwrite`; no Pulse RPC. Serialize each replacement with Tart cloning, without promising a pool-wide transaction. Existing ordinary clones retain their environment; subsequent clones use replacements. Keep old sources if preparation fails. Remote Orchard fleet updates are deferred.

**Slots.** Verify an unused guest with no lease, execution intent, or worker service. Capture boot UUID and MAC; reject duplicate template MACs. Suspend only after readiness. Persist template identity, configuration fingerprint, phase and worker. Jobs clone the untouched suspended source on the same host, preserving all saved hardware. A boot UUID/MAC guard reads the readiness identity inside the clone and rejects cold-boot fallback before lease delivery; do not compare against a host-cached identity from a replaced template. One existing unresolved/active clone reserves its slot; different slots use different MACs. No queue: warming/busy slots decline with `no_capacity`.

**Submit.** Validate complete immutable launches and distinct batch IDs before dispatch. Match a fitting base and slot; use its actual fixed resources. Reject malformed quantities, identities, selectors and empty leases. Decline unsupported runtime caps, start-before deadlines, scratch reservations and unmatched environments/capabilities before side effects. Past deadlines are rejected. Never claim replacement work.

Construct `c2j run with-lease --jobdb … --job-id … --lease-file - --ci --input-mode fail`. Pass the exact opaque lease through stdin, never argv/environment/logs/listings. Pass actual CPU, memory, platform, pinned image/digest and verified capability facts using c2j's supported flags. Pass the resolved concrete base with `--execution-base`; retain `PULSE_BASE` only as diagnostic context. Use a guest c2j version compatible with JobDB v2 leases. Resolve selections to a commit for preparation, failing on lookup errors. Job startup invokes installed tools without installation or release lookup. The lease authorizes c2j to retrieve secrets; the provider receives no job secrets. Preserve LaunchID and full JobRef in durable/native metadata and listings.

**Admission and recovery.** Pulse submits each LaunchID only once. Direct Tart keeps properties in private, atomically replaced `pulse.json` files inside existing VM directories, with no separate inventory or terminal launch ledger. Persist ownership, LaunchID/JobRef, native specification, slot association and preparation/delivery properties before native run. Duplicate currently owned LaunchIDs are rejected. On restart and before admission/reconciliation, rebuild the in-memory index from those directories and observe native state. Missing VMs have no reservation; report uncertain creation errors to the caller for logging. Never retry native clone/run after ambiguity. A partial clone observed by its creating process gets properties for later cleanup; do not adopt untagged unknown directories on restart. Recover only idempotent guest delivery. An optional legacy StateDir imports matching version-3 records for existing VMs without modifying old files. Orchard continues using its private journal, stable duplicate results, uncertain dispatch reservations and terminal history. Accepted means the Orchard create response or local detached Tart dispatch succeeded; boot/delivery/execution may still fail.

**Backend execution.** Orchard uses REST startup scripts, events and power-state updates; labels select workers and must not carry arbitrary correlation fields. Direct Tart uses literal CLI arguments, preserves suspended-clone hardware, checks active MAC collisions, and detaches `tart run --no-graphics --suspendable`. Bind direct job ownership to a private UID marker, directory identity and hardware. Published source directories are replaceable; validate their required hardware and state without requiring the old directory/MAC identity. SSH delivers scripts through stdin. Persist private delivery data so host restart can retry idempotent delivery without repeating native launch. Tart suspension is asynchronous: save the request in the VM properties once, then observe completion without resending the signal, including after restart. Closing the library never kills native jobs.

**Guest lifetime.** Root launchd owns bootstrap/delivery independent of the SSH session. Execute c2j once as the unprivileged worker account after durably recording intent. Bound setup and missing-delivery time, never the runtime of a zero-timeout worker. Shut down after c2j exits. Environment preparation is reusable only in unused image builders; never sanitize an executed VM for another job.

**Reconciliation and listing.** `Run`/`Reconcile` manage lifecycle. `List` is read-only, paginated, scoped, and excludes templates/terminal work. Preserve JobRef and LaunchID; expose no lease. Observation failure is an error, not an empty successful inventory. `Slots` and `Images` expose operational state only. Configuration changes and `Drain` retire idle slot reservations while preserving unresolved jobs and published sources. `PurgeImages` explicitly removes known sources after draining and completing all jobs; unregistered aliases are outside its scope. Missing known unused templates may be rebuilt; Orchard ambiguous creates remain reserved; failed builds are retained for inspection.

**Cleanup.** Never infer worker absence from age, failed status alone, or unreachable SSH. Require a native stopped observation. Recheck exact name, UID and immutable specification before deletion; quarantine mismatches. Direct Tart additionally validates local directory ownership. A suspended job clone whose detached run has exited is terminal, including a failed snapshot restore; a reusable template is not. Kernel-held launch locks distinguish a live startup from a stale PID. Finish when the owned native API/local record is absent; no additional physical-removal proof is required. Never prune by prefix or delete unrelated VMs.

**Security and testing.** Private VM properties and Orchard state directories, atomic fsynced writes, sanitized errors, no redirects, verified controller TLS and explicit insecure lab HTTP. Lease-bearing native delivery records remain private. Optional direct SSH host-key pinning; otherwise trust the managed guest endpoint. Deterministic tests cover API validation, resource/base resolution, c2j invocation, duplicates, unknown dispatches, concurrent reservations, recovery, read-only listing, template identity, cleanup and HTTP/SSH process boundaries. Live tests cover two-slot preparation/resume, host-library reopen, reuse, and real JobDB execution through the public Submit API. A disposable fixture requires `macos-*arm64` and validates JobDB v2 lease execution, Nix execution, lease-bound secret retrieval, renewal beyond the initial lifetime, completion, and completed/expired lease rejection without reacquisition. The full-suite script fails on skipped/missing live assertions and saves redacted, Git-ignored reports before cleanup. Direct Tart live tests run on macOS and additionally update sources while an old clone runs, verify old/new identities, and execute jobs from the replacements.
